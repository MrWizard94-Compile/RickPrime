# RickPrime WPAI Ingestion and Integration Reassessment

Assessment date: 2026-07-25  
Scope: C:\WPAI company workspace discovery plus Software and AI Research integration into the RickPrime desktop workstation  
Posture: native workflow promotion plus governed registry integration; no destructive source-tree merge

## Decision

WPAI is a staged company portfolio with separate local authorities, runtimes, safety policies, and release controls. A literal merge of all repositories into RickPrime would create an uncontrolled blast radius, duplicate fragile services, and weaken StudioOps/Janus human-approval boundaries.

RickPrime therefore integrates in five layers:

1. Company Atlas keeps company-level direction, authority sources, evidence labels, activation gates, and fixed root handoffs.
2. Project Fleet retains every registered Software repository as a detectable, folder-openable node with its own ownership and instructions.
3. Knowledge Forge promotes the reusable deterministic context, provenance, and local-analysis workflow formerly demonstrated by WPAI Explorer into the native workstation.
4. Research Nexus gives the complete identified AI Research portfolio a fixed source-aware and governance-aware control surface without auto-running experiments.
5. Sentinel Array provides workspace-wide, automatic metadata discovery and systems diagnostics while preserving the fixed registries as the authority-bearing integration layer.

## Source basis

The governing company sources are WPAI-CONTEXT.md, WPAI-ROADMAP.md, REVENUE-PLAN.md, and SOULv2.0.0.md at the WPAI root. The AI Research overview and autonomous architecture document establish that the division is pre-work/funding-gated, that research claims need measured baselines, and that StudioOps, HellForge, and Janus must not be replaced with a second orchestrator or task store.

WPAI Explorer is an actual local knowledge application with context search, provenance, graph presentation, and Docker-hosted Ollama integration. Its search engine is deterministic but uses a mock Minecraft corpus, and its server also contains cloud-provider paths. RickPrime uses the deterministic bundle/provenance design only; it substitutes real registered WPAI metadata and preserves its local-only Ollama bridge. It does not copy mock corpus claims, cloud integrations, or the embedded Explorer server.

## Native integrations delivered

### Knowledge Forge

- software and research registry metadata form the only corpus;
- query tokenization creates deterministic bounded result sets;
- each node carries source/provenance availability rather than document contents;
- declared links record known architecture and governance lineage;
- local analysis uses the existing loopback-only Ollama bridge;
- a selected node can only open its fixed registered folder;
- no vector-index count, graph-database claim, arbitrary search, source-code execution, web crawling, provider key, or external API is introduced.

### Research Nexus

- fourteen AI Research roots are mapped with description, tags, source availability, evidence label, gate, ownership boundary, and integration mode;
- source-map nodes are visibility/folder-handoff only;
- Knowledge Forge source nodes contribute bounded metadata/provenance to local context bundles;
- JanusPrime is the sole status-control node and can run only its documented status wrapper;
- no node exposes a generic run, seed, repair, task, loop, crawler, pull, deployment, commit, spend, publish, or credential operation.

### Scroll and dense-workstation behavior

- desktop workspace has a stable main scroll region and a return-to-top control;
- Home, End, Page Up, and Page Down navigate the workspace when an editable control and Omni-jump are not active;
- side navigation, project/research lists, provenance rows, model lists, command output, and long local analyses have contained nested scrolling;
- narrow layouts intentionally use ordinary document scrolling to remain operable on small screens.

### Sentinel Array: WPAI-wide discovery and diagnostics

- scans the fixed WPAI root breadth-first using only directory/file names, directory depth, marker names, and counts;
- detects Git, Node, Python, Rust, JVM, Go, .NET, and authority-document markers without reading any document body;
- treats the entire non-sensitive company tree as reachable through a validated directory handoff, including divisions beyond the prior curated Software and AI Research registries;
- persists only safe structural fingerprints in RickPrime user data so a fresh scan can show safe added or removed entries;
- uses a native Windows filesystem watcher when available, with a bounded 30-second polling fallback;
- reports host CPU/memory/RickPrime-process telemetry, WPAI-volume storage, Docker availability/container count, local Ollama state, and StudioOps runtime summary;
- excludes hidden/runtime folders, credential-shaped names and key formats, symlinks, dependency/build/cache outputs, and dense imported source collections from recursive monitoring. A dense collection root remains visible/openable rather than producing thousands of false portfolio nodes;
- has visible depth/directory/entry caps. A cap is a coverage signal, never a claim that the remainder was scanned.

## Janus verification boundary

The documented Janus status wrapper was executed from C:\WPAI\AI-Research\Janus. It exited successfully and reported a reachable asset queue, 59 tasks across pending, abandoned, failed, and accepted states, while its configured memory and cognition endpoints were unreachable at that moment. This is a point-in-time local status result, not a repair request, progress claim, permission to create work, or reason to enable autonomous research.

RickPrime registers that exact status path with a fixed executable, fixed arguments, fixed working directory, output cap, and timeout. The UI cannot alter the command. Any repair, task, loop, seed, or broader Janus operation remains in the Janus/HellForge ownership domain.

## Coverage gaps and safeguards

1. Company-root presence and document availability are not current commercial, storefront, release, funding, or research-result verification.
2. AI Research contains several folders without a directly identified local project overview. Their registry records are deliberately marked as requiring local review instead of inventing capabilities.
3. Research benchmark/methodology documents are research synthesis until a measured baseline and reproducible artifact are owned by the relevant project.
4. Explorer's older mock corpus and cloud-provider surface were intentionally not treated as company evidence or copied into RickPrime.
5. The system reads no source document body at runtime. Registry descriptions originate from this reassessment and must be updated only when owning evidence or topology changes.
6. Sentinel is not a semantic index: its automatic detection confirms only structural presence and marker names, not ownership, safety, health, license, or current commercial/research state.
7. The runtime has no generic terminal, arbitrary path opener, remote endpoint form, crawler, publish/spend button, or approval bypass. Its dynamic folder handoff can open only a current, non-symlink directory already discovered under C:\WPAI.

## Maintenance rule

Update an owning project’s source and instructions first. Update the fixed RickPrime registry only when company topology, a fixed safe handoff, a source document, a recorded gate, or a bounded native integration changes. Sentinel automatically reflects safe structural additions, but do not treat it as a source of semantic authority or turn it into arbitrary execution.
